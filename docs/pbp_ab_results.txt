PBP_GAME_PACE_L10 ON ITS OWN — 2026-09-25

Question: does game pace earn a place beside DEF_PACE_L10, the only other pace
column any market reads? (r = 0.04 between them, so this is not a redundancy
question. PACE_ROLL correlates 0.82 but NO model reads it, so the A/B I first
proposed — pace against PACE_ROLL — was measuring nothing.)

Setup: scripts/feature_ab.py --layer pbp_pace --markets REB,AST --folds 4,
both arms restricted to the five seasons with event logs (129,059 rows),
validation 2025-01-15 -> 2025-03-29. Each market reads exactly one of the two
columns (PBP_GAME_PACE_L10), so this is a clean single-feature ablation.

ANSWER: NO. It does not earn its place.

Across 32 model/metric rows (excluding `distribution`, which reads no tree
features and is unaffected by construction):

  improving rows clearing their own fold spread : 0
  worsening rows clearing their own fold spread : 2
  best improvement seen                         : 0.84x sd  (not evidence)

The only deltas that clear the threshold are HARM, both on CatBoost/AST:

  AST catboost ECE cal  +0.00275  sd 0.00070  3.93x  worse in 4 of 4 folds
  AST catboost ECE raw  +0.00220  sd 0.00159  1.38x  worse in 3 of 4 folds

11 of 32 rows improved, 21 got worse or stayed flat — about what a coin would
do, except that the one consistent signal points the wrong way.

WHAT THIS DOES *NOT* ESTABLISH. An earlier draft of this note said the gain
from the full pbp layer "is therefore coming from the shot-mix columns". That
does not follow, and the reference was wrong as well. Three corrections:

  - The full-layer table ABOVE in this file is a THREE-fold run over
    2025-10-01 -> 2026-02-13. The four-fold full-layer run referred to is a
    different one (2025-01-15 -> 2025-03-29, same five seasons), and its table
    is not in this file. "Read this against the result above" pointed at the
    wrong table.

  - Neither run shows the layer helping both markets cleanly. In the 3-fold
    table above, REB improves at 3/3 on every model, but AST is MIXED:
    catboost Brier raw +0.00003 (worse, 1/3) and line_aware 2/3, while
    ensemble and xgboost manage 3/3.

  - Subtracting a one-column result from a three-column result does not
    attribute the remainder. Each market reads THREE pbp columns; the layer
    toggle removes all of them at once. Showing that pace alone does nothing
    says nothing about whether the other two carry the gain, whether they
    carry it jointly, or whether pace contributes only in combination with
    them. That needs its own ablation and has not been run.

WHAT IT DOES ESTABLISH, and only this: PBP_GAME_PACE_L10 on its own does not
improve REB or AST on this window, and it measurably worsens CatBoost's AST
calibration error. That is enough to justify dropping it from those two
markets; it is not enough to say where the layer's gain comes from.

The null result is at least consistent with what the column turned out to be:
PBP_GAME_PACE is a GAME constant — every player in a game shares the value —
so after rolling it is close to a team-schedule feature, and the panel already
gives the model opponent context through DEF_* and ELO_*. That is a reading,
not evidence.

RECOMMENDED (not applied — this changes shipped model behaviour):
